# 章节写入与追踪文件更新流程

> 2025-05-09 发现的问题：Chapter 5 因写入流程错误丢失。已修复并固化为规范。

---

## 问题回顾

写第5章时，用一次 `write_file` 调用同时写入「章节正文」和「审核报告」，导致：
1. 审核报告混入章节文件（污染正文）
2. 实际写入的章节内容不完整
3. 文件未正确保存到目标路径

---

## 正确流程

```
写章节前
  → 读文风指南/写作规范
  → 读章节大纲（确认上章/本章概要）
  → 读世界状态（确认人物位置）

写章节
  → write_file(章节文件路径, content=[仅正文，不含审核报告])

写完章节后
  → 读取章节文件自审（内存中，不涉及文件操作）
  → 向用户展示审核报告（不保存到任何文件）
  → 更新追踪文件（章节大纲/编年史/世界状态/剧情线追踪/角色弧光追踪/关系记录/进度看板）

全程：章节文件只写一次，审核报告不写入任何文件
```

---

## 追踪文件更新清单（每章必做）

| 文件 | 更新内容 | 格式 |
|------|---------|------|
| 大纲/章节大纲.md | 追加本章信息 | 状态/字数/核心事件/场景/推进线条/埋下伏笔/世界状态变化 |
| 大纲/编年史.md | 追加时间线 | 故事时间点/事件/章节 |
| 世界观/世界状态.md | 更新人物位置/物品变化 | 表格 |
| 大纲/剧情线追踪.md | 记录线条推进 | L01/L02…状态 |
| 大纲/角色弧光追踪.md | 记录弧光变化 | 角色ID/变化描述 |
| 人物/关系记录.md | 记录关系变化 | 时间/角色A-B/变化/原因 |
| 大纲/进度看板.md | 更新完成数/字数 | 表格 |

## 常见错误

| 错误 | 后果 | 避免方法 |
|------|------|---------|
| 审核报告写入章节文件 | 正文被污染，文件膨胀 | 审核报告只展示不保存 |
| 忘记更新追踪文件 | 设定不一致 | 每章写完立即更新所有追踪文件 |
| 章节文件路径错误 | 文件丢失 | 确认路径：`正文/卷X_名称/第Y章.md` |
| 一次 write_file 多段内容 | 写入不完整 | 分开多次调用 |
| **写章节时用截断标记** | 章节只有几百字（如198行骨架版） | 必须一次写完整再写入，write_file不会自动补全 |
| **字数严重不足（低于设定值80%）就写下一章** | 大量章节不达标需重写 | 每章写完验证字符数在设定值±20%范围内，不达标立即扩充 |

## 输出截断问题的解决方案（2025-05-10 新增）

**症状**：`wc -m` 显示文件只有800-1500字符，内容在段落中间中断。

**根因**：`write_file` 对单次文本长度有限制（约1000字符），超出被截断。

**解决方案：分段写入 + patch 追加**

```
第一段：用 write_file 写入（约800-1500字，完整的剧情段落）
第二段：用 patch 追加（old_string="---"）
第三段：验证 wc -m，不足则继续 patch 追加
第四步：直到达到设定值×80%以上
```

**示例节奏（第21章：2545字符）**：
- write_file(开幕+李坤开打，1559字)
- patch(苦战+险胜)
- patch(赛后反应+第二轮对手)
- patch(四强预告)

**注意**：
- 按剧情自然分段，不硬性规定几段
- 每段800-1500字比较安全
- patch 时 old_string 要唯一
