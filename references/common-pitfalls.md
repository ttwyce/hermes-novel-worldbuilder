# novel-worldbuilder 常见错误与事故

> 来源：2025-05-10 session | 教训：章节只有几百字而非几千字

## 事故0：`---` 是章节文件的保留分隔符（新增 2025-05-10）

**现象**：`verify_chapter.py` 验证章节时，只读取了前几百字就截断了，后面的正文全部丢失。

**根本原因**：章节文件的格式约定——**第一个独立行 `---` 标记**作为正文与审核报告的分隔符。叙事内部使用 `---` 会导致脚本错误地在该处截断。

**示例**（错误）：
```markdown
# 第1章 穿越废物流
正文第一段……
---
王夫人是镇上有名的悍妇……  ← 错误：这里用了 ---
正文第二段……
---
夜深了……  ← 第三个 --- 更不会被读取
**第1章 完**
## 第X章审核报告  ← 这个才是真正的格式分隔符
```

**后果**：
- `verify_chapter.py` 读到第一个 `---` 就停止读取
- 3428字符的章节被错误读成661字符
- 报告章节不合格（实际已达标）

**正确做法**：
- ❌ **章节叙事内部禁止使用 `---` 做分段**
- ✅ 场景转换用空行、空格段、或「」对话分隔
- ✅ 只在文件末尾正文与审核报告之间保留一个 `---`

**验证方法**：
```bash
grep -n "---" 正文/卷一_XXX/第X章.md
# 正常应该只有一个，且位于正文与审核报告之间
```

**修复步骤**（如已误用）：
```bash
# 1. 定位所有 --- 行
grep -n "^---$" 第X章.md

# 2. 保留第一个 --- 之前的内容（保留文件开头的 ---）
FIRST_DASH=$(grep -n "^---$" 第X章.md | head -1 | cut -d: -f1)
head -n $((FIRST_DASH - 1)) 第X章.md > /tmp/clean.md

# 3. 删掉叙事内的分段 ---
sed '/^---$/d' /tmp/clean.md > 第X章.md

# 4. 验证
wc -m 第X章.md
python3 ~/.hermes/skills/creative/novel-worldbuilder/scripts/verify_chapter.py 第X章.md 3000
```

## 事故1：截断标记导致章节缺失

**现象**：章节文件只有几百字，带有 `...[truncated]` / `待续` / `未完` 等占位符。

**根本原因**：`write_file` 只写入你给它的确切文本，不会自动补全。"先占位后补写"的流程根本不存在。

**后果**：文件已保存，只能手动重写。无自动恢复手段。

**正确做法**：
1. 先在脑中或草稿中组织好完整内容
2. 一次性 `write_file` 写入完整内容
3. `write_file` 返回后立即验证字节数

**禁止**：
- ❌ `...[truncated]` / `待续` / `未完` 等任何截断标记
- ❌ 先写开头再写结尾的分段写入（除非内容确实太长需要分两次）

## 事故2：字数不达标就写下一章

**现象**：章节只有2000-2500字，审核时才被发现不达标。

**根本原因**：写完没有立即验证字数，写下一章时才发现上章不够。

**正确做法**：
1. `write_file` 返回后，用 Python 立即读取文件验证字符数
2. 不达标立即扩充，达标后再写下一章
3. 验证公式：设定值±20%合格（如设定3000字则2400-3600合格）

## 事故3：审核报告混入正文

**现象**：章节文件末尾包含 `## 第X章审核报告` 等内容。

**根本原因**：用 tail 删除正文而不是 head 保留开头；或写入时把审核报告一并写入了章节文件。

**正确做法**：
- 审核报告只在对话中输出，不写入任何文件
- 用 `head -n N` 裁剪（保留文件开头），不用 tail
- 裁剪前先 `grep -n "审核报告" 第X章.md` 定位行号

**修复命令**：
```bash
l=$(grep -n "第X章审核报告" 第X章.md | head -1 | cut -d: -f1)
head -n $((l-1)) 第X章.md > /tmp/chX_clean.md && mv /tmp/chX_clean.md 第X章.md
sed -i '/^---$/d' 第X章.md
```

## 事故4：子代理未执行收尾步骤（新增 2025-05-10）

**现象**：子代理写完章节返回"完成"，但追踪文件（剧情线追踪/进度看板/编年史）还是旧的。

**根本原因**：子代理写完章节后未执行追踪文件更新步骤就直接返回。

**正确做法（强制流程）**：
```
子代理写章节（终端heredoc）
       ↓
verify_chapter.py 验证
       ↓
post_chapter.py 自动更新追踪文件 ← 必须执行
       ↓
grep验证追踪文件包含新章节 ← 必须验证
       ↓
全部通过 → 返回"完成"
```

**sub-agent prompt 必须包含的收尾步骤**：
```bash
# 1. 验证章节
python3 verify_chapter.py 第X章.md 3000
# 2. 更新追踪文件（自动）
python3 post_chapter.py "书名" X Y "核心事件"
# 3. 验证追踪文件更新了
grep "第X章" 大纲/剧情线追踪.md
# 4. 全部完成才能返回
```

**post_chapter.py**：位于 `scripts/post_chapter.py`，自动更新剧情线追踪.md、进度看板.md、编年史.md、角色弧光追踪.md。

**禁止**：未执行 post_chapter.py 就返回"完成"

## 事故5：追踪文件未及时更新

**现象**：章节写了但追踪文件是旧的，用户问"更新了吗"才发现漏了。

**正确做法**：写完章节→验证文件→输出审核→**立即自动更新所有追踪文件**→再报告用户完成。不要等用户触发。

## 事故6：上下文压缩产生phantom task list

**现象**：上下文压缩后出现一个"Active Task"任务清单，包含完全不知道的项目（如某个不存在的小说/某章编号），且用户从未提及。

**根本原因**：上下文压缩产生幻觉任务列表，与实际文件系统状态不符。

**验证方法**：当看到可疑的任务清单时，立即用 `ls` 验证：
```bash
ls ~/novels/项目名/正文/
ls ~/novels/项目名/正文/卷一_XXX/
```

**正确做法**：
1. 压缩后如果出现与实际不符的任务列表，忽略它
2. 以文件系统实际状态（`ls`结果）为准
3. 如果用户说"继续写第X章"，先 `ls` 验证当前写到第几章，再决定从哪里继续

## 事故7：字数预估偏差导致章节过短

**现象**：章节规划了3000字，写完只有1900-2400字，需要大量补丁补充。

**根本原因**：实际输出比预估少10-20%，且生成过程中没有中间点检查。

**正确做法**：
1. 规划时按「实际输出=预估×0.8~0.9」的心理模型
2. 要写3000字，规划时应按3300-3500的标准生成内容
3. 每写完一个大段落（约500-800字），用 `wc -m` 实时检查
4. 如果中间点检查发现字数不足预期的60%，立即扩充当前段落再继续
5. 结尾段落要有意做buffer扩充，不要写得太"刚好"

**本session教训案例**：
- ch7：规划2800→实写2351字（差349字）
- ch8：规划2800→实写2070字（差730字）
- ch11：实写仅1941字
- ch12：实写仅1794字
- 根因都是「估算偏差 + 无中间点检查」

## 事故8：post_chapter.py 准确性问题（新增 2025-05-10）

**发现背景**：子代理执行 post_chapter.py 后，用户质疑「准确性怎么样」——发现脚本有4类 bug。

### 8.1 进度看板残留列

**现象**：进度看板中第12章行从4列变成6列：
```
| 第12章 | ✅完成 | 2559 | 新生大比首轮，主角击败对手 | 2559 | 新生大比公布，主角vs对手，女主传音 |
```
（多了 `| 2559 | 新生大比公布，主角vs对手，女主传音 |`）

**根本原因**：脚本只替换了前3列（`\| 第X章 \| [^\|]+\|`），原始行6列的后面几列残留。

**修复**：改用整行正则 `\| 第{chapter_num}章 \| [^\n]+\n?` 匹配并完整替换整行，不依赖列数。

### 8.2 编年史插入位置错误

**现象**：新章节行被插到表格外部（在 `---` 之前），导致表格结构损坏。

**根本原因**：`content.find('\n---')` 找的 `---` 紧跟表格最后一行的下一个 `|` 字符，不是表格真正的结束位置。

**修复**：逐行解析表格——找到 `| 时间 | 事件 | 章节 |` 表头后，逐行扫描以 `|` 开头的行，遇到非表格行结束，精确找到最后一行的位置再插入。

### 8.3 角色弧光追踪无角色检测

**现象**：角色弧光追踪记录只写「待补充」，没有实际内容。

**修复**：添加 `extract_characters_from_chapter()` 函数，从章节文件自动检测出现角色（从数据库读取已注册角色列表），生成带角色名的占位符。

### 8.4 追踪文件重复插入

**现象**：同一章节被插入两次（如角色弧光追踪出现两个 `### 第12章`）。

**原因**：无去重检查，脚本运行多次就重复插入。

**修复**：所有4个更新函数都加了 `if f"第{X}章" in content: 跳过` 检查。

### 使用后验证（必须）

post_chapter.py 运行后**必须验证**追踪文件内容：
```bash
# 验证进度看板：检查第X章行没有多余列
grep "第X章" 大纲/进度看板.md

# 验证编年史：检查新行在表格内，不在---前
grep -n "第X章" 大纲/编年史.md

# 验证角色弧光追踪：只有1个### 第X章
grep "### 第X章" 大纲/角色弧光追踪.md | wc -l
# 期望值：1（不是2）

# 验证剧情线追踪：只有1个### 第X章
grep "### 第X章（已完成）" 大纲/剧情线追踪.md | wc -l
# 期望值：1（不是2）
```
