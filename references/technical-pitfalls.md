# 技术陷阱与避坑指南

> 本文件记录 novel-worldbuilder 技能使用过程中的技术陷阱，供后续使用参考

---

## 陷阱1：init_novel.py 必须用 python3

**问题**：运行 `python init_novel.py` 会报错 `python: command not found`

**原因**：Linux 环境下 Python 3 通常不 alias 为 `python`，需要显式调用 `python3`

**正确做法**：
```bash
python3 /home/admin/.hermes/skills/creative/novel-worldbuilder/scripts/init_novel.py "书名" 150 3000
```

**影响版本**：所有 Linux/macOS 环境

---

## 陷阱2：子代理批量生成全部超时

**问题**：用 `delegate_task` 同时启动多个子代理生成所有文件，全部超时失败

**原因**：
1. 多子代理并行竞争上下文
2. 内容互相引用（角色档案依赖角色注册表）
3. 单次 API 调用生成大量内容耗时不确定
4. 超时后无任何文件写入

**正确做法**：主 Agent 逐文件生成，每次 1 个文件，写入后再生成下一个

---

## 陷阱3：追踪文件中的数字需要人工确认

**问题**：`init_novel.py` 创建的追踪文件（如进度看板）使用传入的参数，但章节大纲.md 等文件是脚本生成的，内容可能需要调整

**正确做法**：
- 创建后检查追踪文件中的数字是否正确
- 特别是「章节总数」和「每章字数」要与用户确认的参数一致

---

## 陷阱4：章节大纲模板格式不一致

**问题**：每章写完后追加到章节大纲时，格式如果不统一会导致后续难以追踪

**正确格式**：
```markdown
### 第X章：章节名
- **状态**：✅已完成
- **字数**：实际字数
- **核心事件**：本章发生的主要事件
- **场景**：地点（与前后章衔接）
- **推进线条**：L01（✓）、L03（×）（标记本章推进了哪些线条）
- **埋下伏笔**：Fxxx（如有）
- **世界状态变化**：人物/物品/地点的变化
```

---

## 陷阱5：伏笔编号重复或跳跃

**问题**：如果多个文件都有伏笔记录，可能出现编号不一致

**正确做法**：
- 统一使用 F001-F010 编号体系
- 每章写完后在伏笔与钩子.md中追加
- 状态标记：待追踪 → 第X章已埋设 → 第X章已回收

---

## 陷阱6：章节大纲中状态标记顺序

**问题**：章节写完后，状态标记可能写错位置

**正确顺序**：
1. 先写章节正文到正文目录
2. 执行章节审核
3. 审核通过后，才在章节大纲中标记 ✅已完成

---

## 陷阱7：write_file 输出截断

**问题**：`write_file` 在内容较大时会在约1000字符处被截断，单次写入无法达到3000字目标。

**症状**：`wc -m` 显示文件只有800-1500字符，而非预期的3000+，内容在段落中间突然中断。

**根因**：`write_file` 工具对单次写入的文本长度有限制，超出后被截断。

**解决方案：分段写入**

```
第一步：用 write_file 写入第一段（约800-1500字，完整的剧情段落）
第二步：用 patch 在文件末尾追加第二段内容（old_string="---"）
第三步：验证 wc -m，不足则继续 patch 追加
第四步：直到达到设定值×80%以上
```

**实战示例（第21章：2545字符）**：
```
write_file(第21章第一段：开幕+李坤开打，1559字)
patch(第21章第二段：苦战+险胜，进入第二轮)
patch(第21章第三段：赛后反应+第二轮对手)
patch(第21章第四段：进入四强预告)
→ 最终：2545字符 ✅
```

**注意事项**：
- 按剧情自然分段，不硬性规定几段
- 每段800-1500字比较安全
- patch 时 old_string 要唯一（用 "---" 或具体段落内容）

**绝对禁止**：
- ❌ 尝试一次性 `write_file` 3000字完整内容（会被截断）
- ❌ 用 `python3 -c "content=..."` 长命令（会失败，File name too long）
- ❌ 用 tail 裁剪文件（会反向删除）

## 陷阱8：终端 workdir 参数不支持中文路径

**问题**：在 `terminal` 工具中使用 `workdir` 参数，且路径包含中文字符（如小说名「时光缓缓」），会报错 `Blocked: workdir contains disallowed character '时'`。

**原因**：`workdir` 参数对非ASCII字符的校验过于严格。

**解决方案**：不使用 `workdir`，改为在 heredoc 重定向中直接使用完整绝对路径（用双引号包裹）。

**错误做法**：
```bash
# 在 terminal 工具中设置 workdir="/home/admin/hermes/novels/时光缓缓" ← 失败
```

**正确做法**：
```bash
cat > "/home/admin/hermes/novels/时光缓缓/正文/卷一_铺垫与启程/第3章.md" << 'EOF'
# 第3章
...
EOF
# 不使用 workdir，直接用完整绝对路径（路径含中文必须加双引号）
```

## 陷阱9：post_chapter.py 第三个参数必须是整数

**问题**：调用 `post_chapter.py` 时，将第三个参数误写为中文标签「字数」，导致 `ValueError: invalid literal for int() with base 10: '字数'`。

**根因**：`sys.argv[3]` 用 `int()` 解析，必须是纯数字字符串。

**错误调用**：
```bash
python3 post_chapter.py "时光缓缓" 3 字数 "核心事件"
#                              ↑ 这是字符串 "字数"，不是数字 → 报错
```

**正确调用**：
```bash
python3 post_chapter.py "时光缓缓" 3 3386 "核心事件" "/完整/路径/第3章.md"
#                              ↑ 实际字数（整数）  ↑ 可选：章节文件路径（让脚本自动检测角色）
```

**注意**：脚本 usage 为 `python3 post_chapter.py <书名> <章节号> <字数> "<核心事件>" [章节文件路径] [伏笔]`
- 第3个参数 `字数`：实际字数（整数），不是标签
- 第5个参数 `[章节文件路径]`：可选，建议传入让脚本自动检测本章出现的角色并更新其弧光

---

## 陷阱10：用户喜欢先讨论再执行

**问题**：用户多次说"你先别执行，现在是讨论问题的时候"，希望确认方向后再行动。

**正确做法**：
- 大规模操作前先询问用户
- 用户明确说"开始写"后再执行
- 不要在用户还没确认方向时就自动执行
